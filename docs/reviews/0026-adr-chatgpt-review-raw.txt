V1.0.7 Roadmap

This ADR creates a very strong foundation.

I would now avoid adding more Stage types and instead consolidate runtime metadata and stage management. A coherent next step would be:

Stage Registry: central registration and lookup of StageDescriptors, enabling discovery, validation, and tooling without relying on scanning runtime objects.

Runtime Metadata Schema (ADR-0027): define and version the structure of ctx.metadata (condition_eval, server_metrics, stopped_by, future tracing fields), so all stages and hooks write to a consistent contract.

Descriptor Validation: add startup-time validation for descriptor uniqueness (e.g. unique name), reserved roles, and incompatible flag combinations such as always_run_after_stop=False on stages intended to execute after termination.

Critical Issue Analysis (Q7)

This is the only issue I would classify as blocking before merge.

The migration helper:

Python
Run
StageDescriptor(name=stage.name)

cannot preserve the existing behavior of CheckpointStage, because always_run_after_stop defaults to False. That would silently change the semantics introduced in V1.0.4.

The clean solution is not to make the compatibility layer smarter through heuristics (hasattr(stage, "store")), because that reintroduces the duck typing this ADR is removing.

Instead, make the migration explicit:

Every built-in stage defines its own descriptor.

The compatibility factory is reserved exclusively for legacy or third-party stages that predate ADR-0026.

That preserves V1.0.x behavior, removes string-based coupling, and keeps the architecture internally consistent. This is the one adjustment I'd require before considering ADR-0026 complete.
