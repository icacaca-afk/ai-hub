## Additional release-gate finding

The first independent rerun exposed two old test modules that were included in
the `not live` suite but still launched the real `explain-route` command against
installed CLIs and browser providers:

- `tests/test_cli_score_integration.py`
- `tests/test_explain_route.py`

This made the claimed non-live gate depend on workstation credentials, CLI
startup time, and browser availability. On the review host the first unisolated
run timed out in `qoderclicn`/provider health probing. The tests were changed to
exercise the real command/dispatcher against a deterministic Demo-only registry
and a non-persistent quota stub. Product routing code, frozen modules, and
Provider implementations were not changed.

The review also reproduced a Windows GBK parent-process decode failure. The
release record now gives the process-local UTF-8 command required on Windows;
no system encoding setting is changed.
