## Scope

This candidate adds a thin, optional 9Router Provider and unifies the remaining
duplicate Provider registry consumers. It does not modify `core/`, `router/`, any
existing Provider, Multi-Agent Loop, 9Router source, accounts, or storage.

The adapter is disabled by default and manual-only. It requires an exact model or
Combo, uses a fixed non-streaming text request, rejects redirects, bypasses proxies
only for loopback, defaults Token Saver to off, and reports gateway/model discovery
as degraded rather than proof of successful execution.

## TDD evidence

The implementation was built in independently committed stages:

1. `f958855` — bounded design and implementation plan;
2. `142f3c8` — immutable, fail-closed configuration;
3. `d90bd68` — bounded HTTP bridge and structured failures;
4. `20b0185` — explicit selection and health semantics;
5. `5f08f56` — canonical CLI/explain/MCP registry;
6. `3724bdc` — bilingual safe-operation documentation;
7. `eddefee` — self-review remediation for auto-route and accounting gaps.

Each implementation stage began with a failing test. The self-review specifically
found that `ScoreRouter` filters on `health()` rather than `Provider.available()`;
the original manual-only guard was therefore insufficient. The remediation makes
pre-selection health unavailable without network I/O and includes a direct
ScoreRouter bypass regression test. It also changes user-facing cost/quota values
from apparent zero/unlimited values to unknown.

## Live boundary

No process was listening on local TCP port 20128 at verification time. Therefore:

- mock-server behavior is verified;
- packaging and installed metadata behavior are verified;
- real 9Router authentication, model discovery, and Chat Completions execution are
  **not verified**;
- no statement is made about a specific upstream model, Combo fallback, account,
  quota, cost, or Token Saver quality.

Live approval requires a pinned 9Router version, a dedicated test credential or
explicit loopback no-auth mode, one approved low-cost/self-hosted target, and logs
that contain no secret or prompt payload.

## Review decision required

Before merge, an independent security/architecture review must decide:

1. whether URL, authentication, redirect, proxy, response-size, error-redaction,
   and manual-only boundaries satisfy ADR-0038;
2. whether sharing the canonical registry with MCP has any compatibility impact;
3. whether the internal `quota_left() == -1` sentinel is acceptable given that
   user-facing `quota_info()` reports unknown;
4. whether live smoke is required before ADR acceptance or may remain a documented
   post-merge activation gate.

Until that review completes, ADR-0038 remains Proposed and this branch must not be
merged or tagged as V1.0.14.
